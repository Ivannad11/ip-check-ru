Что такое утечка DNS

Перед тем как открыть сайт, браузер спрашивает у DNS-сервера его адрес. Список таких вопросов — по сути история твоих посещений.

VPN шифрует трафик, но DNS-запросы иногда идут мимо него — прямо к DNS провайдера. Тогда провайдер видит, куда ты ходишь, а сервисы по резолверу понимают, из какой ты страны. Это и есть утечка.

Некоторые провайдеры ещё и перехватывают запросы на 53-й порт: прописал 8.8.8.8, а отвечает всё равно провайдер.

Нашёл утечку — что делать

Правило одно: при включённом VPN DNS должен идти через туннель или через зашифрованный DoH.

Браузер. «Безопасный DNS» в Chrome / Edge / Яндекс Браузере иногда ходит мимо VPN-клиента. Если клиент сам управляет DNS — выключи эту настройку.

Система. Windows: ipconfig /flushdns. macOS: sudo dscacheutil -flushcache. Убери вручную прописанные DNS в настройках сети.

VPN-клиент. Включи перехват DNS (DNS hijack / fake-ip) или TUN-режим — тогда все запросы пойдут через клиент.

Поправил — запусти тест ещё раз.

Почему DNS течёт, даже когда VPN включён

Клиент не забирает DNS. HTTP/SOCKS-прокси передаёт только TCP. Имя сайта браузер резолвит заранее — и если в клиенте не включён удалённый DNS, запрос уходит провайдеру.

Система и клиент живут отдельно. Часть программ берёт DNS из системы, часть — у клиента. Выходов становится два.

IPv6. Многие правила ловят только IPv4, а AAAA-запросы уходят напрямую.

Раздельная маршрутизация. Если российские сайты идут напрямую, их DNS-запросы тоже могут уходить российскому DNS — это нормально. Плохо, когда российский DNS резолвит и зарубежные сайты: тогда страна видна.

  • TUN-режим — весь трафик, включая UDP-запросы DNS, через клиент;
  • DNS внутри клиента — fake-ip или перехват DNS;
  • DoH / DoT — провайдер не видит содержимое запросов;
  • выключить IPv6, если клиент его не обрабатывает.
Обычный DNS, DoT, DoH — в чём разница

Обычный DNS (порт 53) — открытым текстом, его видят и подменяют. DoT (853) — зашифрован, но порт выдаёт, что это DNS, его легко заблокировать. DoH (443) — выглядит как обычный HTTPS, отделить от сайтов сложно.

AliDNS и DNSPod — китайские, Яндекс DNS — российский: при выходе в другой стране тест пометит их как утечку. Яндекс DNS есть смысл оставлять только для российских доменов при раздельной маршрутизации.

А WebRTC тут при чём

WebRTC — встроенные в браузер звонки. Чтобы узнать свой внешний адрес, он шлёт UDP-запрос на STUN-сервер, и этот запрос часто идёт мимо VPN. Странице не нужно никаких разрешений, чтобы так узнать твой IP.

DNS выдаёт, куда ты ходишь, WebRTC — кто ты. Проверь оба: утечка WebRTC.
